## 離線暫存規格（Yowthi GUIDED 專屬）

### 技術架構

```
Service Worker（vite-plugin-pwa）
    ├─ 快取：當日加工單 API 回應（供離線查看）
    ├─ 攔截：所有 POST/PATCH/DELETE 請求
    │         有網路 → 直接送 API（正常流程）
    │         斷線   → 存入 IndexedDB
    └─ Background Sync：網路恢復後自動依序上傳
```

### 快取範圍

- **當日加工單序號下的所有明細**
- 離線時可查看當日歷史明細
- 離線時可執行：新增明細 / 5分鐘內軟刪 / 5分鐘後沖銷

### IndexedDB 結構

```typescript
pendingRequests: [
  { method, url, body, timestamp, localId }
]
```

### 網路恢復後

- Service Worker 偵測到 `online` 事件
- 依序上傳 IndexedDB 所有暫存請求
- 以 Yowthi 本地資料為主，不做衝突處理
- 上傳完成後清除 IndexedDB 暫存

### 衝突處理原則

- Yowthi 為工廠加工最前線唯一操作者
- Poli / Jeab 帳號不干預 Yowthi 的加工資料
- **以 Yowthi 本地資料為主，直接上傳，無需衝突確認**

## 全系統統一規範

1. **觸控操控**：全系統採用觸控選單模式，點選日期→跳出日期選單，點選基本資料→跳出選取畫面，點選數字→跳出專屬數字鍵盤
1. **基本資料 ID**：全部採用手動輸入，系統設定為必填
1. **作業系統序號**：英文字母 + 日期 + 循環編號（進貨系統為 1～4 循環，其他系統為流水號）
1. **刪除機制**：軟刪（第1次）+ 硬刪（physical delete + AuditLog）；軟刪：ADMIN+OFFICE；硬刪：ADMIN only
1. **日期格式**：泰國格式 D/M/YY
1. **選單顯示規則**：所有觸控選單顯示「圖片 + ID + 名稱」；明細表不顯示圖片
1. **圖片規則**：僅 Master Data 可存 imageUrl；Transaction Tables 禁止圖片欄位
1. **金額計算**：一般交易寫入金額有小數點一律無條件捨去（Math.floor），在 Service 層統一處理；資料查詢的成本分析依 07 正式規格採小數 2 位四捨五入
1. **加工品項**：固定 ID H01/H02/H03，名稱可改，不可新增 ID
1. **數字鍵盤**：小數點最多 1 位，允許輸入 0，無最大值限制
1. **網路斷線**：顯示全螢幕泰語警告；GUIDED 可繼續操作並暫存；其他角色等待恢復

## 進貨單序號規則（重要）

### 格式：`S-YYYYMMDD-N`（N = 1～4，每個進貨品項獨立循環）

- 同一天 + 同一進貨品項 = 只有一張進貨單
- 同一天可有不同進貨品項的進貨單（各自獨立循環）
- N 依該進貨品項最後一張進貨單 +1，到 4 後歸回 1

```
檳榔葉獨立循環：S-20260528-3 → S-20260529-4 → S-20260530-1 → S-20260531-2
玫瑰花獨立循環：S-20260528-2 → S-20260529-3 → S-20260530-4 → S-20260531-1
```
