# YowThi ERP V4.0 — 加工系統規格

> 加工系統是本套 ERP 的靈魂核心模組

-----

## 一、主加工單規則

|項目        |規格                              |
|----------|--------------------------------|
|序號格式      |PO-YYYYMMDD-XXX（orderNo @unique）|
|orderDate |單純記錄日期，不設 @unique               |
|唯一性條件     |**每日 + 相同進貨品項 = 限一張主加工單**       |
|sourceType|RECEIVING（H01/H02）或 DEFECT（H03） |


> 設計原意：同一天不同進貨品項可各自建立一張加工單，為未來擴充多品項做預先安排

## 三、加工品項（固定 ID，名稱可改）

```
H01 → 原料加工（名稱可改，ID 不可改，不可新增）
H02 → 成品加工（名稱可改，ID 不可改，不可新增）
H03 → 瑕疵品加工（名稱可改，ID 不可改，不可新增）
```

> 禁止新增 H04 以上的 ID，否則無法對應作業流程

### H01 / H02 / H03 差異對照

|欄位            |H01 原料加工                     |H02 成品加工                   |H03 瑕疵品加工                  |
|--------------|-----------------------------|---------------------------|---------------------------|
|來源層級          |ReceivingBatch（批次）           |ReceivingOrder（整張進貨單）      |ReceivingOrder（整張進貨單）      |
|選取農民          |✅                            |❌                          |❌                          |
|選取進貨批次        |✅（系統自動或選單）                   |❌                          |❌                          |
|選取進貨單序號       |❌                            |✅                          |✅                          |
|outputQty（完成品）|✅                            |✅                          |✅                          |
|defectQty（瑕疵品）|✅ → 自動建立 DefectPool          |❌                          |❌                          |
|wasteQty（廢料）  |❌                            |✅                          |✅                          |
|完成狀態欄位        |ReceivingBatch.processingDone|ReceivingOrder.h02Done     |ReceivingOrder.h03Done     |
|金額            |同加工單、員工、加工類型合計後捨棄小數|同加工單、員工、加工類型合計後捨棄小數|同加工單、員工、加工類型合計後捨棄小數|

### 加工工資計算版本

- 舊版（`wageCalculationVersion = 1`）：每筆明細以 `floor(outputQty × wageRate)` 計算；既有且未編輯的歷史資料維持原值。
- 新版（`wageCalculationVersion = 2`）：每筆先保留 `outputQty × wageRate` 的精確結果，再依「同一加工單＋同一員工＋同一加工類型」加總，最後只對群組應付總額無條件捨棄小數。
- 既有明細一經編輯即升級為新版規則；同群組內的新版明細會重新分配整數 `amount`，其合計必須等於群組精確工資合計捨棄小數後的結果。
- 單筆畫面顯示精確工資證據；薪資、成本與監控沿用整數 `amount` 加總。包裝工資不在本次變更範圍。

## 四、完整操作流程

```
Step 1：選取進貨品項
    │
    ▼
Step 2：系統自動判斷
    ├─ 當日已有該進貨品項加工單 → 沿用既有加工單序號
    └─ 當日無 → 系統自動建立新加工單（PO-YYYYMMDD-XXX）
    │
    ▼
Step 3：選取員工
    │
    ▼
Step 4：選取加工品項（H01 / H02 / H03）
    │
    ├─── H01 原料加工 ─────────────────────────────────────
    │   Step 5：選取農民（TouchSelectorModal）
    │   Step 6：系統查詢該農民未完成的進貨批次（processingDone=false）
    │            │
    │            ├─ 只有 1 筆 → 自動帶入，直接跳 Step 7
    │            └─ 2 筆以上 → 顯示選單讓員工選擇
    │                          顯示：[品項圖片] 進貨日 D/M/YY (N)
    │                          點選後系統記錄 batchId + farmerId
    │   Step 7：輸入 outputQty（完成品數量，小數點最多 1 位）
    │   Step 8：輸入 defectQty（瑕疵品數量，小數點最多 1 位）→ 系統自動建立 DefectPool
    │   Step 9：輸入工資（小數點最多 1 位）
    │   Step 10：系統計算精確工資，並依同加工單／員工／加工類型合計後捨棄小數
    │   Step 11：確認送出 → 系統驗證 loss ≥ 0
    │
    ├─── H02 成品加工 ─────────────────────────────────────
    │   Step 5：選取進貨單（h02Done=false）
    │            顯示：[品項圖片] 進貨日 D/M/YY (N)
    │            點選後系統記錄 receivingOrderId
    │   Step 6：輸入 outputQty（完成品數量，小數點最多 1 位）
    │   Step 7：輸入 wasteQty（廢料數量，小數點最多 1 位）
    │   Step 8：輸入工資（小數點最多 1 位）
    │   Step 9：系統計算精確工資，並依同加工單／員工／加工類型合計後捨棄小數
    │   Step 10：確認送出 → 系統驗證 loss ≥ 0
    │
    └─── H03 瑕疵品加工 ────────────────────────────────────
        Step 5：選取進貨單（h03Done=false）
                 顯示：[品項圖片] 進貨日 D/M/YY (N)
                 點選後系統記錄 receivingOrderId
        Step 6：輸入 outputQty（次級品數量，小數點最多 1 位）
        Step 7：輸入 wasteQty（廢料數量，小數點最多 1 位）
        Step 8：輸入工資（小數點最多 1 位）
        Step 9：系統計算精確工資，並依同加工單／員工／加工類型合計後捨棄小數
        Step 10：確認送出 → 系統驗證 loss ≥ 0
```

## 五、選單顯示統一規格（H01 / H02 / H03）

所有進貨相關選單統一採用員工友善顯示模式：

```

範例：

[🌿圖片]  29/5/26  (4)

|------|------------------------|-----------------------|-----------------------|
|過濾條件  |該農民 processingDone=false|h02Done=false          |h03Done=false          |

## 六、加工產出資料流

```
ReceivingOrder（進貨單 S-YYYYMMDD-N）
    │
    ├─ ReceivingBatch × N（每農民一批）
    │       │
    │       └─ H01 原料加工（批次層級）
    │               ├─ outputQty → 原料成品
    │               └─ defectQty → DefectPool（系統自動建立）
    │                                   │
    │                                   └─ H03 瑕疵品加工（整單層級）
    │                                           ├─ outputQty → 次級品
    │                                           └─ wasteQty → 廢料
    │
    └─ H02 成品加工（整單層級）
            ├─ outputQty → 最終成品
            └─ wasteQty → 廢料
```

## 七、失重公式

```
H01：loss = inputQty - outputQty - defectQty
H02：loss = inputQty - outputQty - wasteQty
H03：loss = inputQty - outputQty - wasteQty

若 loss < 0 → 禁止儲存
失重比例：(loss ÷ inputQty) × 100
```

## 十、介面設計規範

### 共用規範（所有介面）

- **所有選取操作統一使用 TouchSelectorModal**（詳見 05_UI設計規範.md 第十四節）
- 禁止使用 HTML `<select>` 下拉選單
- 農民、員工、品項選取：搜尋框 + 圖片卡片 Grid（48px 圖片 + ID + 姓名）
- 數字輸入：NumericKeypad 自動彈出

### ADMIN / OFFICE 介面

- 深色 APP 風格，卡片式佈局
- 完整 CRUD 權限（軟刪 + 硬刪，無時間限制）
- 可查看所有欄位：備註、銷售單序號等
- 作業系統模組採用左側步驟導引區 + 右側操控區（電腦版）

### FACTORY 介面

- 同 ADMIN/OFFICE 視覺風格
- 可建立加工單、執行流程、DefectPool、完工確認
- 不可修改主資料

### GUIDED 介面（Phase 4 實作）

- 全螢幕大按鈕導引式操作
- 固定步驟流程，禁止自由跳頁
- 預設泰文
- **永不自動登出**（GUIDED 角色排除 Idle Timeout）
- 隱藏欄位：加工單序號、加工日期、銷售單序號、備註
- **離線操作支援**：斷線後繼續操作，資料暫存 IndexedDB，網路恢復自動上傳

## 十一、刪除保護機制

### GUIDED 介面

|條件      |允許操作              |
|--------|------------------|
|5分鐘內，上一筆|軟刪（僅限最後一筆）        |
|超過5分鐘   |禁止直接刪除，強制導引至沖銷明細流程|

### 沖銷明細流程（超過 5 分鐘的修正）

```
員工點擊某筆明細「修正」
    │
    ▼
系統導引：新增扣除明細
    ├─ 扣除量 = 原始 outputQty（強制全額沖銷，不允許部分沖銷）
    ├─ 員工確認送出
    │
    ▼
系統詢問：「是否要新增修正明細？」
    │
    ├─ 選「是」→ 導引至一般新增流程（無任何時間或數量限制）
    │
    └─ 選「否」→ 關閉導引，僅完成單筆全額沖銷
```

**沖銷規則：**

- 全額沖銷，扣除量必須等於原始 outputQty，不允許部分沖銷
- 沖銷明細的員工ID與原始明細相同，不可更改
- isOffset = true 標記

### ADMIN / OFFICE 介面

- 軟刪 + 硬刪（physical delete + AuditLog）
- 無時間限制

```
